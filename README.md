# XOps Platform

MVP внутренней платформы AI Copilot на Vue 3 и TypeScript. Каталог, поиск и открытие приложений работают в одном интерфейсе. Copilot с собственным UI встраивается через iframe; для остальных доступен универсальный демонстрационный чат.

## Локальный запуск

Нужен запущенный Docker Desktop с Linux-контейнерами или Docker Engine с Compose. Приложение запускается исключительно через Docker:

```sh
docker compose up -d --build
```

Откройте [http://localhost:8080](http://localhost:8080). Остановка:

```sh
docker compose down
```

Сборка автоматически запускает линтер, проверку форматирования, типов и модульные тесты. Порт привязан к `127.0.0.1`; публикация на серверы и CI/CD не настроены.

### Корпоративные материалы

Шрифты и PDF-гайд **не хранятся в Git и не включаются в Docker-образ**. `.gitignore` исключает `mts_shrift/`, гайд и файлы шрифтов; `.dockerignore` исключает их из контекста сборки. Исходные локальные файлы сохраняются.

Compose подключает каталог `mts_shrift/ШРИФТ/Web` только для чтения к `/brand-fonts`. Можно хранить шрифты полностью вне проекта: скопируйте `.env.example` в `.env` и задайте `MTS_FONTS_DIR` абсолютным путём к каталогу `Web`. В Windows используйте прямые слеши, например `C:/brand/mts/ШРИФТ/Web`.

Нужны WOFF2-файлы в исходной структуре:

```text
Web/
  Text/MTSText-Regular/MTSText-Regular.woff2
  Text/MTSText-Medium/MTSText-Medium.woff2
  Text/MTSText-Bold/MTSText-Bold.woff2
  Extended/MTSExtended-Medium/MTSExtended-Medium.woff2
  Extended/MTSExtended-Bold/MTSExtended-Bold.woff2
```

Основной красный `#E30611`, белый и серые взяты из предоставленного гайда, раздел 03.01. Светлый фон приветственного блока использует оттенки дополнительных синего `#0082C8` и фиолетового `#913F98`. Текст выровнен по левому краю согласно разделу 04.01. Используются предоставленные MTS Text и MTS Extended; резервный Arial указан в гайде как дополнительная гарнитура. PDF для запуска не нужен.

Если локальных шрифтов нет, интерфейс использует Arial. Для фирменного оформления подключите предоставленные материалы: они намеренно не распространяются с исходниками.

### Настройка адресов

Адреса приложений задаются в `config/runtime.json`, который подключён в контейнер только для чтения:

```json
{
  "applications": {
    "test-agent-alpha": "http://2.59.80.61/dev/test-agent-alpha"
  }
}
```

Измените адрес и обновите страницу; пересборка не нужна. Если редактор заменяет файл целиком и bind-mount продолжает видеть предыдущую версию, выполните `docker compose restart platform`. Для другого порта задайте `XOPS_PORT` в `.env`.

Тестовый Copilot: [Demo](http://2.59.80.61/dev/test-agent-alpha), [Swagger](http://2.59.80.61/dev/test-agent-alpha/api/docs). Его API не вызывается: платформа встраивает существующий UI, а контракт универсального чата пока неизвестен.

## Архитектура

| Модуль            | Назначение                                                                     |
| ----------------- | ------------------------------------------------------------------------------ |
| `src/domain`      | Внутренняя типизированная модель Copilot, статусы, поиск, интерфейсы адаптеров |
| `src/services`    | Mock-каталог, mock-чат, runtime-конфигурация, клиент проверки iframe           |
| `src/app`         | Vue Router, внедрение зависимостей и общее состояние загрузки каталога         |
| `src/composables` | Состояние чата, повтор ответа и отмена незавершённого запроса                  |
| `src/views`       | Каталог, общая страница `/copilots/:id`, неизвестный маршрут                   |
| `src/components`  | Карточки, чат, iframe, навигация, состояния загрузки и ошибок                  |
| `src/styles`      | Корпоративная типографика, токены и адаптивные стили                           |
| `server`          | Раздача статической сборки и локальная проверка возможности встраивания        |
| `tests/e2e`       | Браузерные проверки desktop и mobile                                           |

Composition API и внедрение сервисов через `provide/inject` отделяют UI от источников данных. Отдельный глобальный state manager для этого MVP не нужен. Для backend достаточно реализовать `CatalogRepository` и `ChatGateway` и заменить адаптеры в `src/main.ts`. Внутренняя модель не объявляется будущим контрактом API.

### Добавление Copilot

Добавьте запись в `mockCopilots` в `src/services/mock-catalog.ts`. Она автоматически появится в каталоге, поиске и общем маршруте. Для чата:

```ts
{
  id: 'new-copilot',
  name: 'Новый помощник',
  description: 'Описание задач помощника.',
  status: 'available',
  icon: 'sparkles',
  interfaceType: 'chat',
  applicationUrl: null,
}
```

Для отдельного UI используйте `interfaceType: 'iframe'`, `applicationKey: 'new-copilot'`, `applicationUrl: null` и добавьте соответствующий адрес в `config/runtime.json`. Адаптер заполнит `applicationUrl`. Допустимы только HTTP/HTTPS-адреса без учётных данных. Статусы: `available`, `maintenance`, `coming-soon`. После изменения mock-каталога пересоберите контейнер. Менять компоненты и маршруты не требуется.

### Встраивание приложений

Независимый UI открывается в sandboxed iframe, общая навигация остаётся доступна. Локальный сервер сначала проверяет HTTP-ответ и заголовки `X-Frame-Options` / `Content-Security-Policy: frame-ancestors`, включая перенаправления. Проверка ограничена адресами из runtime-конфигурации; произвольный URL через запрос передать нельзя. Это служебная проверка iframe, а не мониторинг и не API статусов каталога.

Сетевые ошибки, HTTP-ошибки, отсутствующий адрес, запрет встраивания и таймаут показывают сообщение с повторной попыткой. Сервер не обходит и не удаляет политики безопасности удалённого приложения.

Браузер не предоставляет родителю надёжный доступ к содержимому cross-origin iframe: событие `load` может сработать и на странице ошибки. Поэтому после загрузки остаётся действие «Приложение не отображается», которое показывает состояние ошибки без ухода с платформы. Проверка заголовков не гарантирует работоспособность внутренних API, SSO или cookies стороннего приложения. Если сервер и браузер получают разные политики либо сам UI выполняет новое перенаправление, это действие позволяет корректно обработать проблему. Для HTTP-приложения используйте локальную HTTP-платформу или настройте HTTPS-адрес сервиса.

## Проверки качества

```sh
docker compose --profile test run --rm --build checks
docker compose --profile test run --rm checks npm run security
docker compose --profile test run --rm --build e2e
```

Первая команда запускает ESLint, Prettier, `vue-tsc`, проверку типов серверных модулей, Vitest и встроенный Node test runner. Сборка `platform` повторяет эти проверки перед Vite build. Аудит зависимостей использует `npm audit --audit-level=high` и требует сети.

Браузерные тесты работают с приложением в Docker. Образ `e2e` устанавливает Chromium при первой сборке. Тесты проверяют поиск, адаптивность, загрузку MTS Text, чат, навигацию, iframe, запреты встраивания, неизвестные маршруты и восстановление после ошибки конфигурации. Удалённый UI и ошибки в этих тестах подменяются на уровне сети, поэтому результат не зависит от внешнего сервера.

Для форматирования исходников через контейнер:

```sh
docker compose --profile test run --rm -v .:/workspace -w /workspace checks /bin/sh -c 'PATH=/app/node_modules/.bin:$PATH prettier --write .'
```

Ruff, Mypy, Bandit и Pytest не применяются: в проекте нет Python-кода. Используются инструменты Vue, TypeScript и Node.js.

## Временные интеграции и ограничения MVP

- Каталог и статусы — локальные демонстрационные данные, без backend и получения runtime-статусов.
- Чат — явно обозначенный mock, без вызовов LLM или выдуманного API Copilot.
- Авторизация и SSO — демонстрационный пользователь; полноценного входа нет.
- История чата хранится в памяти текущей страницы и очищается при переходе к другому Copilot или перезагрузке.
- Дополнительные помощники демонстрационные; `test-agent-alpha` использует предоставленное внешнее приложение.

Дальнейшие точки расширения: адаптер реального каталога с проверкой ответа на границе, API чата, согласованный handshake для встроенных UI и подключение корпоративного SSO. Рейтинги, избранное, отзывы, администрирование, Kubernetes и CI/CD в MVP не включены.
