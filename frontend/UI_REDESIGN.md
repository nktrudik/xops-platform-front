# XOps Platform — UI redesign v2

Ветка `feature/ui-redesign-v2` создана от актуального `origin/dev` (`af86eab`). Это основное приложение с существующими авторизацией и API, без экспериментального переключателя и mock-данных в рабочих маршрутах.

## Интерфейс

- Общая оболочка: графитовая боковая навигация, компактная шапка, аккаунт и выход, справка по форматам работы. На мобильных — нативное модальное меню с Escape и управлением фокусом.
- `/` — главная с данными каталога: количество Copilot, доступных инструментов и представленных форматов. Без вымышленных показателей активности.
- `/catalog` — полный каталог. Поиск, формат, доступность и вид сохраняются в URL (`q`, `interface`, `available`, `view`). Доступны карточки и список.
- Карточки одинаковы для всех инструментов, используют имя, описание, иконку, статус и формат из существующего API. Загрузка, пустой ответ, отсутствие результатов, ошибки и фоновое обновление обработаны отдельно.
- При большом каталоге браузер откладывает отрисовку содержимого карточек за пределами экрана. Вёрстка проверена на 80 элементах и длинных названиях, а также при ширинах 320, 768, 1024 и 1440 px.
- `/copilots/:id` сохраняет универсальный чат с Markdown, историей, повтором запроса и удалением диалогов, Embedded UI и переход к внешним продуктам. Их сервисы и API-контракты не менялись.

Фирменные MTS Text / MTS Extended, красный `#E30611`, графитовые и нейтральные поверхности. Компактная типографика, единые радиусы и сдержанные состояния hover/focus. Движение отключается существующим правилом `prefers-reduced-motion`.

## Локальный запуск

Из `frontend`:

```powershell
npm.cmd exec vite -- --host 127.0.0.1 --port 5173 --strictPort
```

Открыть `http://127.0.0.1:5173/`. Vite запускает только frontend; для самостоятельного входа, каталога и чатов требуется существующий same-origin API платформы. Обхода авторизации и демонстрационной сессии в приложении нет.

Для локальной оценки шрифтов dev-плагин `local-fonts.ts` читает имеющиеся файлы из `../mts_shrift/ШРИФТ/Web`. Плагин работает только при `serve`: шрифты и гайды не копируются в `public`, `dist` или Git. В production сохранён существующий механизм загрузки `/brand-fonts/`.

## Проверки и скриншоты

```powershell
npm.cmd run check
npm.cmd run build
npm.cmd exec playwright test -- --config playwright.redesign.config.ts
```

Браузерная конфигурация запускает реальный frontend в установленном Chrome на 1440×900 и Pixel 7. Существующие сценарии каталога, polling, ошибок и Embedded UI сохранены. Добавлены вход/выход, справка, мобильное меню, фильтры с перезагрузкой, переходы из каталога в чат и Embedded UI, восстановление и удаление диалога, пустой и большой каталог.

HTTP-фикстуры подключаются исключительно из Playwright через `page.route`: это проверка frontend по существующему контракту, а не проверка доступности живых удалённых Copilot. Рабочие маршруты всегда получают данные через `createCatalogRepository` и `createChatGateway`.

Скриншоты: `../.artifacts/ui-redesign-v2/` — `home`, `catalog`, `chat`, `embedded`, `login` для desktop/mobile и `navigation-mobile.png`. Просмотрены реальные снимки, исправлены перекрытие мобильной навигацией и фокус, затем сценарии прогнаны повторно.

Новые зависимости не добавлялись, `package.json` и lock-файл не менялись. `npm audit` продолжает отмечать существующую high-уязвимость dev-зависимости `undici@7.30.0` через `jsdom`; обновление зависимостей не входит в редизайн.
