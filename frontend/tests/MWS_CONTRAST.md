# MWS Contrast: визуальная проверка

26 октября 2026. Классическая версия, ветка `main`, исходный commit `c034fc0`.

## Результат

- Официальный компактный SVG MWS из header [mws.ru](https://mws.ru/): знак, favicon, доступное имя, композиция XOps Platform и подпись footer. [Происхождение ассета](../src/assets/brand/README.md).
- Платиновый header, графитовая активная навигация, отдельные поверхности аккаунта и выхода.
- Контрастные фильтры: графитовый selected, красный счётчик, видимые границы default, hover и клавиатурный focus. Сохранены API-подсчёты, поиск и URL-состояние.
- Карточки с графитовым блоком формата, светлой кнопкой открытия, более чёткими границами, статусами с текстом, усиленными линиями и анимацией их прорисовки на hover.
- Семантические tokens для поверхностей, selected, hover, focus и границ. Более насыщенное окружение Liquid Ribbon и заметный поиск.

WebGL renderer, backend, API, маршрутизация, CI/CD, Kubernetes и конфигурации окружений не изменены. Новые зависимости не добавлены.

## Снимки и итерации

[Галерея до/после](../../.artifacts/mws-contrast/review.html) переключает размер окна и состояние интерфейса. [Сравнение desktop](../../.artifacts/mws-contrast/comparison-desktop.png), [сравнение mobile](../../.artifacts/mws-contrast/comparison-mobile.png).

Исходные снимки сделаны перед изменениями на том же main и тех же данных. Проверены 1920×1080, 1440×900, 1366×768, 1280×720, 1024×768 и 390×844; отдельно длинные данные при 320 и 768 px.

В `.artifacts/mws-contrast/{before,after}/<размер>/` находятся:

- `page-full.png`, `page.png`: главная с двумя Copilot-ами.
- `header.png`: логотип и навигация.
- `catalog-all.png`, `catalog-chat.png`: выбранные фильтры.
- `card-hover.png`: hover на устройствах с указателем.
- `search-focus.png`: поиск с фокусом.
- Дополнительно после изменений: `filter-focus.png`, `login.png`, `checks.json`.

После первого просмотра уменьшена область декоративных линий: на мобильном они пересекали длинное название. Кнопка открытия стала светлой на графите и красной при hover/focus. Скорректирован отступ каталога, чтобы при 1440×900 первая строка карточек помещалась целиком. После axe исправлен контраст текстовой кнопки сброса: 4,33 → 5,39:1.

Каталог дополнительно проверен с 0, 1, 2, 6, 12 и 30 элементами, всеми статусами, загрузкой и ошибкой API. Эти снимки находятся в `.artifacts/mws-contrast/states/`. В сценариях количества карточек используется reduced motion и существующий SVG fallback. На основных сравнительных снимках используется настоящий WebGL, приостановленный кнопкой интерфейса.

Итого 108 browser-сценариев прошли в соответствующих наборах с учётом повторной проверки исправленного контраста. Полный check не обозначается как успешный: lint, type-check и unit-тесты выполнены отдельно. Форматирование чужих файлов и обновление зависимостей не включены в визуальное изменение.

Axe не нашёл нарушений в каталоге и пустом результате поиска на desktop/mobile; это не полная сертификация WCAG. Дополнительно проверены вычисленные CSS-контрасты: выбранные фильтры и навигация 16,19:1; белый счётчик на красном 4,88:1; доступный статус 6,10:1; границы фильтров и выхода 3,39:1, поиска 4,07:1. Статусы подписаны текстом. Reduced motion, отсутствие WebGL, потеря/восстановление контекста, остановка при скрытии и очистка при навигации проверены.

Все пять локальных шрифтов MTS Text / MTS Extended загрузились с HTTP 200. Горизонтальных переполнений и ошибок консоли на основных снимках нет. При 1440×900 hero — 372 px, карточки — 252 px, низ первого ряда — 899 px. Локально WebGL отрисовывает примерно 60 кадров/с на desktop и 30 на touch, при паузе — 0. Это измерения текущей машины, не гарантия производительности другого устройства.

Проверки используют существующие API fixtures через Playwright route interception. Реальный Vue-интерфейс и WebGL запускаются в Chrome; интеграция с действующим PROD backend в этой задаче не проверялась. Деплой и push не выполнялись.

## Воспроизведение

Из каталога `frontend`:

```powershell
npm.cmd run lint
npm.cmd run type-check
npm.cmd test
npm.cmd run build
npm.cmd exec playwright -- test tests/e2e/mws-contrast.spec.ts --config playwright.mws.config.ts
npm.cmd exec playwright -- test tests/e2e/premium.spec.ts tests/e2e/premium-catalog.spec.ts --config playwright.mws.config.ts
$env:AXE_SOURCE='../.artifacts/classic-premium/qa-tools/axe.min.js'
npm.cmd exec playwright -- test tests/e2e/premium-accessibility.spec.ts tests/e2e/platform.spec.ts tests/e2e/catalog.spec.ts tests/e2e/classic-lifecycle.spec.ts tests/e2e/classic-performance.spec.ts --config playwright.mws.config.ts --project=1440x900 --project=390x844
npm.cmd run security
```

Для axe нужен локальный browser bundle axe-core; использован уже имеющийся QA-ассет версии 4.14.0. Без `AXE_SOURCE` axe-сценарий явно пропускается. Скриншоты, отчёты и HTML-галерея локальны и исключены из Git через существующий `.artifacts`.
